# 机场出站请求与批次时间预算

本文完成[开发计划](NEXT_STEPS.md)第 5 项的时间预算部分，基于已合并的 [Session 隔离和 DNS pinning](OUTBOUND_HTTP.md)。适用于节点、机场信息和后台机场刷新；不改变 Agent 网络行为或部署层停止参数。

## 默认值与计时方式

| 边界 | 默认值 | 行为 |
| --- | --- | --- |
| 连接/读取等待 | 30 秒 | 保留 `timeout`，每次使用时受剩余总预算限制 |
| 单次 `safe_get` | 60 秒 | 从入口起算，DNS、地址切换、TLS、全部跳转及正文共用截止时间 |
| 每跳 DNS 等待 | 10 秒 | 同时受单次/批次剩余时间限制，不能重置总预算 |
| 节点或信息批次 | 180 秒 | 每批最多 5 个抓取线程，共享截止时间；排队时间也消耗预算 |
| 机场抓取的系统 DNS 解析 | 最多 8 个 | 包含已超时、但系统调用尚未返回的解析；满额直接拒绝，不排无限队列 |

截止时间使用 `time.monotonic()`，不受系统时间校准影响。以上是内部常量，不是新增环境变量或 Web 配置。`timeout` 和 `total_timeout` 必须是有限正数，拒绝布尔值、空值、零、负数及 NaN/无穷大。

## 内部接口

`safe_get(..., total_timeout=60.0, deadline=None, stop_event=None)` 保留原参数和完整响应返回语义。`deadline` 是本进程单调时钟的绝对时间；有效截止时间取它与“当前时间 + total_timeout”的较早者。禁止把 Unix 时间戳传入这个参数。`stop_event` 是可选的 `threading.Event`。

- `OutboundTimeout` 继承 `requests.Timeout`：总预算或 DNS 等待超时。原有更短的连接/读取超时仍可能返回 Requests 自身的超时子类。
- `OutboundCancelled`：检测到停止标志。
- `OutboundCapacityError`：8 个系统解析槽位均占用，立即失败。持续满额时应排查宿主解析器；已返回的槽位自动恢复，不启动额外的无限线程。

异常消息只含固定说明；机场调用方继续只记录异常类型，不输出包含订阅身份的异常正文。

`fetch_airport_item(..., deadline=None, stop_event=None)` 和 `fetch_single_airport_info(..., deadline=None)` 在网络前和解析后检查批次期限。`fetch_airport_proxies` 从入口创建一次 180 秒预算；`get_airports_info` 在来源快照和有限重试之前创建预算，配置变化重试不重新获得 180 秒。单节点 provider 使用 `safe_get` 默认 60 秒网络预算。订阅 API 因来源变化重新调用节点批次时，会创建新一批预算；180 秒不是整个 HTTP API 的强制返回上限。

## DNS、连接与慢流

系统 `getaddrinfo` 不支持安全的线程强杀。解析运行在有容量限制的 daemon 线程中；调用线程仅等待限定时间。超时后不释放仍在运行的解析所占槽位，直到系统调用实际返回。迟到线程只有自己的结果容器及槽位，没有 Session、socket 或缓存提交回调，因此不能继续连接或写入缓存。解析器恢复后自动释放容量；daemon 解析线程不单独阻止 Python 进程退出。

每次请求有一个 daemon 截止时间监视线程。它跟踪本请求实际创建的 TCP socket 及 TLS 包装后的 socket，在到期时执行 `shutdown`，打断响应头或正文的阻塞读取；请求所属线程负责关闭响应、连接池和 Session。即使远端持续滴流，或发送 `Connection: close` 导致连接对象提前解绑 socket，仍保留该 socket 的跟踪引用。正常结束会唤醒并结束监视线程。

TCP 连接和 TLS 握手的 socket 超时受当时剩余总时间限制，切换地址、跳转均不续期。每个响应块、EOF 和下一跳前再次检查期限；到期引发的 EOF、协议错误或 TLS 错误会按预算原因上报，不能把截断正文当成成功订阅。

停止标志在 DNS 等待和监视线程中按最长 50 毫秒间隔检查，尝试中断已跟踪 socket。已经进入的底层 TCP/TLS 操作不保证立即响应停止，仍受所设置的连接/握手超时限制；50 毫秒是检查间隔，不是操作系统调度或完整取消保证。

## 批次结果与关闭边界

到期后未开始的节点来源返回空列表；已超时来源按现有缓存补齐规则处理，不绕过来源代次、不允许不完整刷新覆盖完整节点缓存。信息批次的未开始/超时来源返回 `error: "OutboundTimeout"`，仍沿用既有错误信息缓存 24 小时的行为，可在控制台强制刷新。

180 秒约束批次的**网络阶段和新请求准入**。YAML 解析、解压中的 CPU 工作、线程调度、配置锁等待及磁盘读写不能通过 socket shutdown 强杀，可能使函数返回晚于截止时间。解析完成后会丢弃已超时的该来源结果；截止前完成的来源仍可参与原有合并/缓存提交。没有在另一个线程里放任继续运行的完整 HTTP 请求。

后台停止标志同时传到活动请求和队列；仍保留[后台生命周期](AIRPORT_BACKGROUND.md)的停止后禁止开始提交、实际线程退出标志及额外等待 5 秒规则。已经开始的原子写入不能撤回，进程退出不承诺 5 秒硬上限；最终强制停止由 Uvicorn/systemd/容器策略决定。

## 验证与升级回滚

`test_outbound_budget.py` 覆盖真实 HTTP 响应头/正文滴流、停在 TLS 握手的连接、阻塞 DNS/容量/迟到结果、停止、跨跳/地址预算、过期通知和孤立进程退出。`test_outbound_tls.py` 验证真实加密正文的超时。`test_airport_budget.py` 验证节点与信息批次共享期限、跳过排队来源、来源重试不续期以及停止/解析后结果丢弃。原有缓存并发、TLS 身份与 DNS pinning 回归保持。

无 HTTP schema、持久化格式、依赖或 Agent 升级。慢于新预算的机场可能从此前最终成功变为超时，节点依旧按现有缓存回退；首次无缓存且来源不完整时继续返回既有错误。发布前用受控来源检查响应耗时和宿主 DNS，不使用真实订阅凭据作为测试日志。
