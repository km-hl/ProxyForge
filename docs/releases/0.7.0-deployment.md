## 生产升级与恢复

所有者在明确授权完整备份、隔离恢复通过后升级的条件下批准执行。首先在独立目录构建固定来源镜像，旧 Controller 在构建期间继续运行。切换前重新确认实际镜像、Compose、数据挂载、权限、写入者及在途任务；没有活动 Agent、job、deployment 或 chain。

停止目标 Controller 并确认退出后，冷备整个 data 及存在的 SQLite/WAL/SHM、模板历史、缓存、凭据配置和事务记录，同时保存配套 Compose、容器状态与环境来源。备份仅 root 可读，位于 data 之外；文件清单、内容摘要、UID/GID 和权限均核对，并完成备份同步落盘。

从该真实冷备恢复独立副本，在 `--network none`、无发布端口且不共享生产 data 的容器中完成：

- 固定非 root 身份启动，SQLite integrity/foreign key 检查和 schema 5 校验。
- 原模板、手动节点、来源、凭据与历史保持，Mihomo 和 Egern 订阅返回有效文档；没有用空配置代替真实数据。
- 模板保存返回 200，过期 revision 返回 409，再恢复原模板字节。
- 新镜像重启后状态保持；随后用旧镜像启动同一份已运行过新版的恢复副本，验证旧镜像回滚及订阅可用。

全部演练通过后，生产数据槽从冷备重新恢复，不采用发生过模板演练写入的副本。只切换目标服务的镜像与 data source；原端口、网络/别名、既有环境值和凭据保持。新镜像的 Python 环境默认开关生效，未重建其他服务。演练容器已正常停止，旧镜像、原数据槽、完整冷备及私有操作证据保留。

## 回退与未验收范围

已验证的回滚是对真实数据隔离副本使用旧镜像；没有把已运行的生产系统切回旧版。后续如需生产回退，先核对新写入、撤销和远端动作，冷备当前完整集合，再按[恢复流程](../RELEASE_ACCEPTANCE.md)停写并恢复匹配的镜像、Compose 和整套数据。不能混用新旧 DB/key/历史，也不能把旧快照当作无损分布式回滚。同机私有备份不等于异地灾备。

以下项目继续未验收，不能由本次同宿主 HTTPS、CI、完整 VM 或正式 Release 替代：

- 所有者暂缓的独立网络、其他平台公网、裸机安装及 iOS Egern 实机导入/握手。
- 真实公网长任务租约续期、超时后的故障重领，以及直连/链路 TCP/UDP 与全部代理协议握手。
- 真实系统剪贴板字节完整性：本机浏览器界面显示复制成功，但测试浏览器虚拟剪贴板不能证明系统剪贴板结果。

Controller 生产升级已经完成；[开发计划](../NEXT_STEPS.md)的全部验收尚未完成。私有备份、日志、站点路径及原始响应保留在运维记录，不作为公开附件上传。
