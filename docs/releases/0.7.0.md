# ProxyForge Controller 0.7.0 发布说明

首个 Controller 正式版本号为 **v0.7.0**；Agent 软件版本仍为 **0.6.0**。正式版本号表示发布身份，验收范围以下文为准。发布文件中的 `release.json` 固定完整来源提交及兼容关系，`SHA256SUMS` 固定其余四个附件；不使用浮动 master/latest 作为安装来源。

## 新增功能

本次首次版本化交付现有订阅与托管节点控制面：Mihomo/Egern 原生订阅、规则资源、模板版本与历史恢复、Agent 注册/心跳/任务队列、可选 sing-box helper、直连 Reality 和 SS2022 落地/链路管理。能力和客户端限制见[项目中文说明](https://github.com/km-hl/ProxyForge/blob/v0.7.0/README.md)及[Egern 转换契约](https://github.com/km-hl/ProxyForge/blob/v0.7.0/docs/EGERN_EXPORT.md)。这些能力的既有开发阶段不因首次发布而被记为新协议。

控制台“服务器 → 添加服务器”提供可直接复制的 Agent 安装命令，固定官方源码提交和双层 SHA256。注册凭据在目标终端隐藏输入，不放入命令、URL 或 shell history；helper 另行显式安装。完整命令、配置和失败恢复见[Agent 安装指南](https://github.com/km-hl/ProxyForge/blob/v0.7.0/docs/AGENT_INSTALL.md)。

所有项目说明均有中文正文或完整中文入口。项目采用 MIT，Agent 分发保留许可副本；第三方依赖、浏览器资源及可选内核继续遵守各自许可，见[许可说明](https://github.com/km-hl/ProxyForge/blob/v0.7.0/docs/LICENSING.md)。

## 修复

机场刷新移出事件循环；缓存使用来源快照、失效代次和统一锁顺序，避免旧请求在配置变化后回填。机场信息按批次合并，并在提交时与最新状态汇总；原子替换避免读取半写文件。原子文件替换不代表多个 Controller 可以共享写入。

AirportService、内部来源类型及管理/公开订阅路由已整理，保留外部字段、顺序、未知来源字段、缓存格式和完整 37 路径契约。解析和文件读取只对预期数据错误回退；意外内部故障传播到对应隔离边界，避免伪装为空的成功结果。日志不再直接输出异常原文、订阅地址、来源别名或校验内容。

模板 YAML 校验中的真实数据错误继续返回原 400；RuntimeError、MemoryError 等内部解析故障改为固定中文 500，并仅记录异常类型。保存、全局导入和历史恢复在该阶段失败时不写入新模板、历史或 revision。普通订阅校验仍返回原 422 详情，服务日志仅记录错误数量。这是明确的内部故障状态码修正。

## 安全变更

出站 HTTP 隔离 Session 和环境代理继承，将经过公有地址检查的 DNS 结果固定到实际连接，保留原 Host/SNI 和证书验证；限制重定向、响应大小、DNS 等待、单请求与批次总预算。完整边界见[出站 HTTP](https://github.com/km-hl/ProxyForge/blob/v0.7.0/docs/OUTBOUND_HTTP.md)及[预算说明](https://github.com/km-hl/ProxyForge/blob/v0.7.0/docs/OUTBOUND_BUDGETS.md)。这些网络预算不保证 CPU、锁竞争、文件系统操作或整个进程退出的硬实时上限。

Controller 运行时升级，生产依赖及镜像输入锁定；正常容器固定 UID/GID **10001:10001**、移除 capabilities 并开启 no-new-privileges。已有 root-owned 数据必须先冷备再显式迁移，不通过放宽权限或回退 root 启动绕过检查。锁定构建输入不代表镜像逐字节可复现。

Agent 新安装来源携带 MIT：源码提交 `2b8ea5873c7932b12b092a4321e92429ecdc9c19`，源码归档 SHA256 `71b96112d1d6ef167815de464b6d29602e46fe9910e0f770748a67da1e9c10f6`；bootstrap 提交 `15d6e819f30cc678d5b759b62bef39a2568e3d85`，脚本 SHA256 `4db985c1a5e4d7e63f9bde3c85f36afb55f61db500ef0b31ab2fb2ee025ba5c1`。归档的 236 个文件与 Git 对象核对，安装白名单为 25 个 Agent 文件。许可副本由 root 所有且不可由 Agent 写入。

## 数据格式变化

本次稳定性和结构整理不新增数据库迁移：当前 schema **5**，Agent **0.6.0**，现有能力协议版本保持 **1**。早期 schema 1–4 的阶段说明是历史记录，不能替代当前升级流程。模板历史、部署密钥、缓存及 API 的兼容约定继续有效。

发布清单独立记录 Controller `0.7.0`、Agent 版本、schema 基线及各能力协议。旧未标注 Controller 版本的 manifest 继续为 `null`；带版本清单必须由支持该字段的可信校验器独立固定预期版本和 hash，不能混用旧校验器。附件校验方法见[候选发布说明](https://github.com/km-hl/ProxyForge/blob/v0.7.0/docs/RELEASE_AUTOMATION.md)。

## 升级步骤

1. 按[发布验收与恢复流程](https://github.com/km-hl/ProxyForge/blob/v0.7.0/docs/RELEASE_ACCEPTANCE.md)核对当前代码、镜像、Compose/覆盖文件及挂载，保存旧版本，不覆盖工作树改动。等待执行中的部署任务结束，停止所有 Controller 写入者；先冷备整个 `data/`、存在的 SQLite WAL/SHM、配套 `deployment.key`、`.env` 和部署配置，核验备份可读取并在隔离副本演练恢复。备份包含秘密，不上传到公开附件。
2. 核对 v0.7.0 tag、发布记录中的完整提交及 `release.json` 预期 SHA256，再下载和校验附件。下载后自行计算出的 hash 只能作一致性检查，不能代替可信发布记录。Controller 先升级，Agent 按需逐台升级。
3. 根据[非 root 权限迁移指南](https://github.com/km-hl/ProxyForge/blob/v0.7.0/docs/CONTAINER_PERMISSIONS.md)检查目标文件系统和 UID 映射，在停机及冷备后先只读检查，再显式执行迁移。正常服务只使用单个 Controller 进程、单副本；不要配置多个 worker 或多个写入副本共享 data。
4. 在目标环境构建并启动固定代码，核对 UID 10001、持久化权限、健康状态、管理鉴权、原订阅凭据、模板冲突保护、Agent 心跳与实际所用任务。镜像运行、业务请求和公网代理握手分别记录；未完成的验收不因发布文件校验成功而通过。

## Agent 与 helper

Agent 核心模块与当前 0.6.0 相同，Controller 版本升级不自动升级已有 Agent，也不自动安装 helper 或打开代理监听。新固定来源增加分发许可；已有机器不能重跑首次安装命令。

如需升级，先停止 Agent、runtime socket/helper，结束或用原版本恢复执行中的事务，私密备份已安装模块、units、`/etc/proxyforge-agent/` 和整个 `/var/lib/proxyforge-runtime/`。只从同一已核验来源更新匹配模块和 units，不单独写能力标记。已有旧 helper 需核对 CAP_SETUID 修复及 unit 更新步骤，见[安装指南的 helper 说明](https://github.com/km-hl/ProxyForge/blob/v0.7.0/docs/AGENT_INSTALL.md)和[中文 Agent README](https://github.com/km-hl/ProxyForge/blob/v0.7.0/agent/README.zh-CN.md)。旧安装仅缺少 LICENSE 时，显式 helper 安装保留原模块一致性校验并复制许可。

## 验证与已知限制

发布前须复核固定提交的完整 CI 与实际合并树。对应功能已覆盖 Python 3.9–3.13 的单元/集成检查、56 项前端测试、Mihomo 33 个解析场景、非 root 容器恢复及真实 sing-box/systemd 生命周期；Windows 本地 575 项 Python 检查中 30 项平台相关检查跳过，不将跳过计为 Linux 实测。

[PR #70](https://github.com/km-hl/ProxyForge/pull/70) 的 52 项 CI 全部通过，固定许可来源的安装矩阵覆盖 Ubuntu 22.04/24.04 × amd64/arm64 原生运行器四组合、Debian 12/13 × amd64/arm64 原生 systemd 容器四组合，以及 Debian 完整 VM 四组合。测试检查真实固定下载、TTY 注册、测试 CA 下的 HTTPS 心跳、安装许可权限及显式 helper 操作。push 与 PR 两轮合计 52 个 CI 检查，不代表 52 个平台；最终通过状态以相应 PR 和发布来源提交的记录为准。

**所有者已暂缓独立网络、其他平台公网、裸机与 iOS Egern 实机验收，上述项目仍未验收。** 历史同宿主 KVM 公网注册/心跳/短队列任务证据不代表独立网络，也未证明真实公网长任务续租、故障重领和全部代理握手。当前发布不附带生产升级；本候选在生产目标上的镜像启动、冷备恢复、现有 Agent 升级及公网业务验证仍需执行。CI 的测试 CA 不能代替公网证书和真实网络验收。

## 回滚方式

停止新 Controller 及所有写入者，保留失败证据；按升级前记录恢复旧镜像/代码、Compose/覆盖文件、`.env` 与整套匹配冷备，包括数据库、存在的 WAL/SHM、部署密钥、模板历史及事务文件。按旧版本需要恢复数据所有权与权限；不把新旧数据库、key 或单个模板文件拼接成恢复集合。

恢复快照会恢复旧撤销状态和任务状态。先隔离 Agent 同步，核对备份之后的撤销、任务与远端实际部署，再放行。Agent/helper 需各自恢复匹配模块、units 和完整 runtime 备份；Controller 回滚不会自动逆转远端动作，也不保证分布式动作恰好执行一次。保持旧镜像及备份直到目标环境验收完成。
