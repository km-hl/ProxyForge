# 中文发布说明模板

复制本模板的以下结构到 `docs/releases/<不带 v 的版本>.md`，把标题版本和每一处“待填写”替换为本次已经核实的内容，并提交到要发布的同一候选提交。没有变化的项目写“本次无变化”，不能留空或把未验收项写成通过。模板本身不表示已有版本、Release 或部署。

```text
# ProxyForge Controller 待填写 发布说明

## 新增功能

待填写：本次新增能力及使用入口。

## 修复

待填写：实际修复的问题、触发条件与结果。

## 安全变更

待填写：出站、凭据、日志、权限或其他安全变化及适用边界。

## 数据格式变化

待填写：Controller schema、配置文件与兼容边界；没有变化也明确写出。

## 升级步骤

待填写：升级前冷备、副本恢复、单进程限制、权限迁移和切换步骤。

## Agent 与 helper

待填写：Agent 软件版本、各能力版本、是否需要升级 helper、已有安装的升级流程。

## 验证与已知限制

待填写：固定候选提交的本地/CI 证据、具体平台矩阵、未验收与暂缓项目；不把历史部署当作本次部署。

## 回滚方式

待填写：旧镜像/代码、Compose 与匹配数据/密钥的恢复方式及不能自动逆转的远端状态。
```

发布说明必须为 UTF-8，允许 LF、CRLF 或 UTF-8 BOM，工具保留 Git 中的原始字节。八个二级标题必须保持上述顺序，每节有中文内容；代码、协议字段和第三方正式名称可保留英文。避免相对文件链接在 GitHub Release 正文中失效；使用对应发布 tag 的完整官方链接。
