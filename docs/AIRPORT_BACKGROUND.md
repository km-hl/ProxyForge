# 后台机场刷新与关闭管理

本文对应[下一阶段计划](NEXT_STEPS.md)第 1 项，依赖已完成的[节点缓存并发保护](AIRPORT_CACHE_CONCURRENCY.md)、[原子写入](AIRPORT_CACHE_ATOMIC.md)和[信息缓存汇总](AIRPORT_INFO_CACHE.md)。

## 调度与响应

Controller 启动完成配置引用检查后，保存一个后台调度任务到 `app.state.airport_updater`。重复启动调用不会创建第二个活动任务。启动检查和每次完整刷新均通过 `asyncio.to_thread` 执行，同步配置锁、文件读取、网络拉取、缓存补齐及提交不再占用事件循环。

保留启动后等待 300 秒、每轮完成后等待 4 小时的行为；失败也等待相同间隔再尝试。下一轮必须等上一轮完成，每批最多 5 个机场同时拉取。线程提交或刷新失败只记录固定说明及异常类型，不输出异常正文中的订阅凭据或路径。

后台网络或磁盘等待期间，登录状态等不依赖配置锁的 API 仍可响应。需要同一配置锁的 API 仍可能等待短暂的缓存提交；本改动不承诺所有接口都不等待。

## 停止与提交边界

关闭时先设置本轮生命周期的 `threading.Event` 停止标志，再取消调度任务。调度任务以 `asyncio.shield` 等待实际刷新，取消调度不会把仍在运行的线程误报为已完成。应用关闭钩子最多额外等待刷新任务 5 秒；超时记录诊断并保留任务引用。

同步刷新在读取快照前、快照后、网络完成后，以及取得配置锁并完成缓存补齐后检查停止标志。停止后尚未开始的机场队列项跳过抓取；停止标志也传入活动请求，以中断 DNS 等待和已跟踪 socket 的响应读取。线程返回后不能开始缓存提交。来源修改、删除和全局导入仍受原有来源快照与失效代次保护。

通过最后检查、已经开始的原子提交不能被撤回：关闭可能与这一小段写入重叠。正常关闭等待其结束；若底层文件系统长时间阻塞，超过 5 秒后也可能仍在完成该次提交。强制停止进程时仍适用原子写文档的完整文件/临时残留边界，不能把关闭超时当成所有磁盘写入都已结束的证明。

`thread_done` 单独记录同步线程实际退出；不能只根据 asyncio Future 的取消/完成状态判断。旧线程未退出时，同一应用对象再次启动会明确失败，避免开启第二轮后台网络请求。正常退出后可以再次启动新的生命周期。

## 超时的实际含义

机场请求保留 `timeout=30` 的连接/读取等待，并使用 60 秒单次网络总预算、每跳最多 10 秒 DNS 等待和每批 180 秒共享网络截止时间。持续滴流会被中断，过期队列项不再联网；系统 DNS 最多 8 个 daemon 解析线程，迟到结果丢弃。详见[出站时间预算](OUTBOUND_BUDGETS.md)。解析、配置锁与底层文件系统阻塞仍可能使整轮超过 180 秒，不能把网络预算当成整个刷新函数或进程退出的硬上限。

5 秒仅约束应用关闭钩子的额外等待。Python 无法安全强杀已运行的线程，事件循环默认执行器和进程退出仍可能等待这些线程；最终进程退出上限由 Uvicorn、systemd 或容器停止策略决定。不要据此在线清理临时文件，也不要声称 5 秒内一定完成进程退出。本项未更改部署层强制停止参数。

## 内部接口与兼容性

- `refresh_airport_cache(stop_event=None)`：一次同步刷新；不传停止标志时兼容原有内部调用。
- `fetch_airport_proxies(sources=None, stop_event=None)`：保持返回节点列表、来源命名和池大小；共享 180 秒网络截止时间，可跳过停止或过期后的队列项，并把停止标志和截止时间传入单个来源。
- `AirportUpdaterState`：保存停止标志、调度任务、工作任务和真实线程完成标志，仅存内存。
- `startup_event()` / `shutdown_event()`：沿用 FastAPI 启动与关闭钩子，管理任务引用和有界等待。

HTTP 接口、机场信息缓存 24 小时、节点内存缓存 12 小时、数据库 schema 5、Agent 0.6.0 均不变。仍仅支持单 Controller 进程/单副本。

## 验证与发布

`tests/test_airport_background.py` 使用受控 Event 验证刷新不占用事件循环、网络/磁盘等待中的真实 ASGI 请求、调度间隔、轮次不重叠、重复生命周期、失败恢复、排队任务停止、关闭有界等待、晚返回结果丢弃、来源变化、缓存补齐与不完整结果保护，以及 Future 取消后真实线程状态。测试不用等待生产的 300 秒或 4 小时。

原有缓存并发、原子写、鉴权、订阅生成及真实内核 CI 继续执行。P0 四项代码已实现，不代表已部署或完成生产验收；部署仍按[发布验收流程](RELEASE_ACCEPTANCE.md)进行，不能将单元测试当作实际公网验收。

本项无需迁移数据或升级 Agent。回滚使用此前完整 Controller 代码/镜像，保留当前运行配置和缓存；回滚会恢复后台刷新阻塞事件循环与缺少关闭管理的旧行为。
